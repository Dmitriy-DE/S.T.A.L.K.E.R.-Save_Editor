# X-Ray container — M06 evidence

Исследование выполнено 2026-09-15. Эта запись разделяет публично известную
схему контейнера и то, что реально можно принять для этого проекта. Она не
содержит игровых сейвов и не заменяет корпус проверок.

## Публичное исследование

- В открытом [stalker-tools `save_tool.py`](https://github.com/stalker-tools/tools/blob/main/save_tool.py)
  чтение начинается с трёх little-endian `u32`: `magic`, `version` и
  `unpacked_len`. Реализация принимает `magic == 0xffffffff`, отбрасывает
  версии ниже 2 и распаковывает оставшийся поток как raw LZO1X с ожидаемой
  длиной `unpacked_len`.
- В той же реализации после распаковки читаются little-endian chunk-записи
  `type,size`; среди известных типов есть ALIFE, SPAWN, OBJECT, GAME_TIME,
  REGISTRY и SCRIPT_VARS. Это полезное направление для дальнейшего чтения,
  но не доказательство расположения денег или инвентаря.
- В разборе [Valentin Pi формата SoC](https://github.com/valentinpi/valentinpi.github.io/blob/master/posts/soc/soc.md)
  показана запись внешнего заголовка `-1`, `ALIFE_VERSION`, исходный размер,
  затем raw LZO1X-1. Приведённый в статье образец имеет версию `0x0003`.
  Статья отдельно отмечает, что повторное сжатие может дать другие байты,
  хотя игра загрузила пересобранный файл. Поэтому «распаковать и снова сжать»
  не доказывает byte-for-byte round-trip.
- Публичный [xrWiki Save Unpacker](https://xray-engine.org/index.php?action=mpdf&title=S.T.A.L.K.E.R._save_unpacker)
  документирует unpack/repack-инструмент и историю поддержки SoC, CoP и CS.
  Это подтверждает наличие внешнего исследовательского материала, но не даёт
  SHA-доказательства для конкретных версий и Enhanced Editions этого проекта.

## Что доступно локально

Команда проверки корпуса в рабочем дереве 2026-09-15:

```text
rg --files -g '*.sav' -g '*.bak' -g '*.scop' .
```

Результат — пустой. В репозитории нет реального сейва X-Ray, пары
«исходный/контролируемо изменённый», файла после загрузки игрой или безопасно
публикуемого корпуса. Синтетические S.T.A.L.K.E.R. 2 fixtures не подходят для
M06 и не используются как доказательство X-Ray. Личные сейвы, скачанные сейвы
и их байты в Git не добавлялись.

## Решение

M06 **заблокирована по отсутствию корпуса**. Публичная документация позволяет
сформулировать гипотезу декодирования, однако не подтверждает одновременно:

1. границу и варианты заголовка для SoC, CS, CoP и каждого заявленного
   Enhanced/Legends издания;
2. допустимые версии и способ различать игру/издание по содержимому;
3. механизм сохранения исходного сжатого потока или иных байтов,
   необходимый для SHA-256 round-trip;
4. отказ на чужой игре, обрезанном файле и мусоре на реальном X-Ray корпусе.

Поэтому в M06 не добавляются формат, compressor/decompressor, offsets или
эвристический detector. Денежные поля и записи инвентаря намеренно не ищутся.

## Что требуется для разблокировки

Нужен контролируемый внешний корпус, который владелец может предоставить
вне Git либо прогнать локально:

- минимум по одному реальному `.sav` SoC, CS и CoP для каждой конкретной
  версии/издания, которое будет заявлено поддержанным;
- лучше — три независимые пары для последующих полей M07/M08, где между файлами
  известно, что менялось;
- SHA-256 исходного файла, первые 12 байт, успешная распаковка и длина payload;
- пересборка без изменений с SHA-256 исходного файла;
- для случаев, где compressor меняет байты, отдельное доказательство
  preservation-механизма, а не принятие отличающегося SHA;
- позднее — controlled edit, загрузка копии самой игрой и повторное сохранение.

До появления этого корпуса M07, M08 и M09 не могут честно перейти к коду.

## Локальный gate

Код приложения в M06 не менялся. После обновления evidence и статусов:

```text
PYTHON=.venv/bin/python make check
PYTHON=.venv/bin/python make test
```

Ожидается полный существующий Linux gate; зелёный gate не снимает блокер
отсутствующего X-Ray корпуса, Windows runtime или проверки загрузкой игры.
