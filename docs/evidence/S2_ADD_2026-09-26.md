# S2 item addition — what the game does (2026-09-26)

Pair: two real saves of one play session (private). Save A: 511 109 coupons,
44 inventory items. Save B, after buying and looting: 459 086 coupons, 63 items.

## Findings

- **No new object records.** All 19 items that appear in B already exist in A
  as world/stash objects with the same handles (`0x30000e80` … `0x30008578`).
  The highest handle is `0x3000874a` in both saves.
- Picking up or buying changes ownership: the handle joins the player's owned
  handles (44 → 63) and the grid (28 → 47 placed handles); the object record
  stays where it was (record offsets unchanged).
- Stack growth (bandages 34 → 46, 5.45 122 → 235 …) is a count change inside the
  existing record, the path ED-3 already confirmed in the game.
- Kinds seen among the new items: 2 (artifacts), 3 (scopes), 5 (ammo), 8 (quest
  items, PDAs, keys).

## Consequences for ED-2

1. **Transfer (preferred first stage):** give the player an object that already
   exists in the save (stash, world loot) by adding its handle to the owned list
   and a free grid cell. This is exactly what the game writes, needs no handle
   allocator and no new name-table rows.
2. **Clone (second stage):** a copy of an existing record with a fresh handle
   above the maximum. The game never did this in the sample; it needs its own
   L5 check.
