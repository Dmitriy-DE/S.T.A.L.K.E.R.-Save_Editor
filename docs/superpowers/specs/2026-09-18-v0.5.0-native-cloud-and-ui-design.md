# v0.5.0 — In-project Steam Cloud, autodiscovery hints, and UI overhaul

> Historical design. Its helper fallback was removed under SC-2; current
> runtime uses the native worker and Steam CEF web/CDP (PR #8).

Status: approved design (brainstorming), pending spec review
Date: 2026-09-18
Target release: v0.5.0
Branch: `feat/v0.5.0-native-cloud`

## Problem

The user wants to do everything from one place inside the editor:
download cloud saves, edit them, upload them back — without any external
third-party tooling and without fighting FUSE. Concretely:

1. **Steam Cloud is broken and external.** The Cloud tab shells out to a
   third-party `SteamCloudFileManager.AppImage`. On the user's machine it
   fails at startup with `dlopen(): error loading libfuse.so.2` — the system
   has `libfuse3.so.4` but not `libfuse2`, which AppImage type-2 requires.
   The user does not want to depend on someone else's project at all.
2. **Clear Sky path autodiscovery looks broken.** Selecting Clear Sky did not
   visibly pull in the Steam root / game folder / save folder.
3. **Clear Sky inventory shows too many "неизвестно".** Columns read
   "неизвестно" and it looks like data loss.
4. **S.T.A.L.K.E.R. 2 UI is broken.** Overlapping text, cut-off fields,
   janky scrolling, and too many "не разобрано / неизвестно" values, plus it
   is unclear what is actually editable.

## Hard constraints (non-negotiable reality)

- **Steam Cloud requires Valve's native `libsteam_api.so` + a running Steam
  client + the game's `app_id`.** There is no HTTP API and no pure-Python
  replacement. Every path to Steam Cloud — including Steam itself — goes
  through this library. We can eliminate the *third-party helper project*, but
  never the Valve library.
- **Live S2 cloud cannot be verified in the build session.** The user has no
  S2 install and no Steam session available here. The native worker is unit-
  tested against a ctypes fake; the live download/upload round-trip is the
  user's responsibility once the game is installed. Docs must say "not
  verified live" — no false claims.
- **S2 GVAS body is not deeply parsed.** Location/time show "не разобрано"
  because the UE5 GVAS property tree is not walked; only CRC, money, and the
  inventory snapshot are decoded. Full GVAS parsing is out of scope for this
  release; we only surface what is safely extractable and label the rest
  honestly.

## Chosen approach (option A)

Write our own in-project cloud worker; keep the proven helper path as an
automatic, silent fallback so the release never ships a dead cloud tab.

### Section 1 — Steam Cloud

**New: `editor/steam_native.py` — `SteamNativeWorker` plus bounded parent
transport.** The ctypes worker implements the existing `CloudSession` protocol
(`start`, `connect`, `close`) plus `CloudTransport` (`list_files`, `read_file`,
`write_file`, `sync`, `wait_persisted`) — a drop-in for
`steam_cloud.SteamWorker`. The Qt-facing `SteamNativeSubprocessWorker` runs
each native operation in a short-lived child with a hard timeout; this boundary
is required because Python cannot interrupt a hung `ctypes` call. The child
internals use `ctypes` over `libsteam_api.so`:

- `SteamAPI_Init` / `SteamAPI_Shutdown`, `SteamAPI_RunCallbacks`.
- Flat `ISteamRemoteStorage` accessor + `GetFileCount`,
  `GetFileNameAndSize`, `GetFileTimestamp`, `FileRead`, `FileWrite`,
  `FileExists`, `FilePersisted`.
- Requires a `steam_appid.txt` (written to the child process cwd with the
  target app_id) and a running Steam client.
- Reuses `steam_cloud`'s constants (`APP_ID`, `SAVE_PREFIX`, `MAX_FILE_BYTES`)
  and the `_refuse_automated_live_session` guard so automated tests can never
  touch the live S2 cloud.

**New: `editor/steam_backend.py` — `make_cloud_worker`.**
A `WorkerFactory` that returns a `SteamNativeWorker` when
`SteamAPI_Init` succeeds, else a helper-based worker. Failure to initialise
native must be caught and logged, never raised to the UI. Injected into
`ui/cloud_view.py` in place of the bare `SteamWorker` default
(`worker_factory`/`helper_finder` DI already exists — changes are small).

**`libsteam_api.so` locator** (in `editor/platforms.py`, next to
`discover_helper`): search order (1) installed game/Steam runtime,
(2) extracted AppImage payload. Return a `Path | None`.

**Auto-extract without FUSE (fixes the current crash, and is the fallback).**
The helper path must stop depending on FUSE. On use, if the helper is an
AppImage, run `--appimage-extract` (verified to work with no FUSE) into a
cache dir under the app data dir once, then spawn the inner
`squashfs-root/usr/bin/SteamCloudFileManager` directly with
`LD_LIBRARY_PATH` pointing at the extracted payload. Cache keyed by AppImage
mtime/size so re-extraction only happens when the AppImage changes.

**Tests:** a ctypes fake standing in for `libsteam_api.so` exercising
init/list/read/write/sync/failure-to-init; extraction logic tested against a
fixture directory; backend fallback selection tested (native-ok → native,
native-fail → helper). Existing fake transport suite stays green.

### Section 2 — Clear Sky (and all games) path autodiscovery hints

The settings fields are *manual overrides*, intentionally blank. The bug is
that the discovered path is invisible, so it looks like nothing was found.

- When a field is empty, show the auto-discovered path as a real hint below
  the row: "Автопоиск: <path>" when found, or
  "Автопоиск: ничего не найдено — задай вручную" when not.
- Verify Clear Sky discovery actually resolves on Linux/Proton layouts
  (`_XRAY_SAVE_DIRS['clear_sky'] = ('Stalker-STCS',)` and EE variants); add
  missing candidate roots if discovery genuinely misses.
- No behavioural change to override precedence (save dir → game dir → Steam
  root → autodiscovery).

### Section 3 — Clear Sky "неизвестно"

X-Ray parsing already extracts ammo count, condition, money. Columns the
X-Ray format does not expose (weight, size, some type-keys) must render as
"—" with a tooltip "формат не хранит это поле", not the alarming
"неизвестно". Where a field *is* extractable, populate it. Never fabricate
values.

### Section 4 — S2 UI overhaul

This is a real layout pass, not cosmetics. Across Overview, Inventory,
Faction, Cloud, Settings views:

- **Fix overlap/clipping.** The Overview summary block and "Отношения с
  группировками" overlap; summary text is clipped. Replace fixed heights /
  absolute placements with proper layouts, word-wrap, and elide-where-needed.
- **Fix scrolling.** Remove nested/janky scroll areas; one predictable scroll
  per view; tables get their own horizontal scroll only when needed.
- **Fix cut fields.** Inputs and labels must size to content; no truncated
  values in the money/balance/relations rows.
- **Reduce genuine "unknown".** Investigate S2 fields that *should* be
  knowable and are cheaply/safely extractable from the container metadata
  already parsed (item counts, grid cells, orphan counts are already known —
  surface them clearly). Location/time stay "не разобрано" (GVAS out of
  scope) but get an explanatory tooltip instead of a bare label.
- **Clarify editability.** Editable vs read-only/experimental must be
  visually obvious (enabled controls vs. disabled + reason tooltip). Money
  stays labelled experimental; the affordance makes clear what a stage/commit
  actually does.

Scope guard: no new save-format features here beyond honest surfacing of
already-parsed metadata. Deep GVAS parsing is explicitly deferred.

## Components and boundaries

| Unit | Purpose | Depends on |
|------|---------|-----------|
| `editor/steam_native.py` | In-process Steamworks RemoteStorage client | `ctypes`, `libsteam_api.so`, `steam_cloud` consts |
| `editor/steam_backend.py` | Choose native vs helper worker | `steam_native`, `steam_cloud`, `platforms` |

| `ui/inventory_model.py` (edit) | "—" + tooltip for absent fields | — |
| `ui/*_view.py` (edit) | Layout overhaul | PySide6 |

## Error handling

- Native init failure → log + fallback to helper; UI shows the same Cloud tab.
- No `libsteam_api.so` and no helper → clear message + download-helper CTA.
- All existing fail-closed upload semantics (`CloudReceipt`, backups,
  `wait_persisted`) are preserved unchanged.

## Testing

- Unit: native worker (ctypes fake), extraction, backend selection,
  discovery hints, inventory "—" rendering.
- Manual (user, post-release): live S2 cloud download → edit → upload.
- Regression: full existing suite green.

## Out of scope

- Deep S2 GVAS property-tree parsing (location/time editing).
- Vendoring Valve's SDK into the repo/release.
- Any live Steam automation from tests.
