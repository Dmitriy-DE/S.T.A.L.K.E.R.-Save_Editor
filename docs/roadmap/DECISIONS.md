## D1. Кнопка «Добавить» — ждёт владельца

- Предложение владельца: кнопка должна работать, а не быть серой.
- Проверено: на ТЧ и ЧН кнопка есть и работает (`add_items=True`, каталог найден на реальных сейвах). На S2 её нет, потому что нет подтверждённого способа создать запись предмета.
- **Рекомендация:**
  - откатить «серую кнопку»;
  - на трилогии сделать кнопку заметной и удобной (ED-1);
  - на S2 не показывать, пока не готово ED-2;
  - S2 add делать по стадиям: сначала «дублировать предмет, который уже есть в сейве», затем «SID из таблиц сейва», затем «любой SID». Каждая стадия с L5.

## D2. Поставить S.T.A.L.K.E.R. 2 обратно — ждёт владельца

- Без установленной S2 невозможны L5-проверки: S2 add (ED-2), стаки (ED-3), позиция (TP-5), контент из файлов игры (CP-4).
- **Рекомендация:** поставить к волне 3. До этого S2-работа — только чтение и названия.

## D3. Правка стаков S2

- Найдено (подтверждение замечания Codex): writer есть, в документации 0.7.1 обещано, но `edit_stacks = research`, и UI запись блокирует.
- **Решение:**
  - сейчас исправить документацию и добавить тест, который не даёт документации и реестру расходиться (ST-6, RL-4);
  - перевести в `experimental` только после L5 (ED-3).

## D4. Медиа из игр прямо в проекте — ждёт владельца

- Предложение: не вытягивать медиа из игр каждый раз.
- Проверено: аудио уже извлекается один раз и кэшируется; иконки трилогии и S2, а также названия уже поставляются с приложением.
- **Рекомендация:**
  - Названия и иконки поставлять и дальше. Это короткие метаданные и маленькие PNG; у каждого файла будет записан источник (CP-1).
  - Музыку, звуки, текстуры и описания GSC в приложение **не класть**: это прямое распространение чужих ресурсов, и риск жалобы или DMCA на релиз реальный.
  - Вместо этого — локальный content pack: извлекается один раз, у него есть отпечаток сборки игры, пересобирается только после обновления игры (CP-3), статус виден в «Проверить окружение» (RL-3).
- Если владелец всё же хочет встроить музыку, это отдельное осознанное решение, и в первую очередь в desktop, не в web.

## D5. Переписать на C# — ждёт владельца

- Предложение: переписать на C# под все платформы, включая Mac; Codex может портировать.
- Вердикт: **да**, но side-by-side и только после того, как есть оракул:
  - сначала Python-версия даёт golden-векторы на корпусе сейвов (CS-1) и лабораторию корпуса (RL-5);
  - затем новый репозиторий (`S.T.A.L.K.E.R.-Save-Editor-Next`): .NET 10 LTS + Avalonia 11, Core без UI;
  - Codex портирует модуль за модулем до паритета, Claude делает архитектуру и ревьюит каждый PR;
  - порядок: readers → writers по одной capability с L5 → UI → Steam, updater, пакеты.
- Python остаётся рабочим продуктом до переключения (CS-8). macOS не ждёт C#: MAC-1 делается на текущем стеке.
- Почему не big bang: форматы, Kraken, cloud-транзакции и десятки writer-кейсов. Без паритета по векторам переписанное «скомпилируется, но не работает».

## D9. Автопубликация — ждёт владельца

- Проверено: CI падает на publish, потому что в репозитории **нет ни одного секрета**.
- **Решение:**
  - GitHub Release создаётся в CI без секретов (через `GITHUB_TOKEN`);
  - R2, APT и web deploy выполняются только при наличии секретов, а при их отсутствии джоба явно пропускается, а не падает (ST-8).
- Владелец сам (я токены не трогаю):
  1. Cloudflare API token с правами R2 Edit, Workers Edit, Pages Edit.
  2. Секреты: `gh secret set CLOUDFLARE_API_TOKEN`, `gh secret set CLOUDFLARE_ACCOUNT_ID`.
  3. APT: экспортировать **существующий** ключ (новый не генерировать) в `APT_SIGNING_KEY` и `APT_SIGNING_KEY_ID`. Если ключ отдавать в GitHub не хочется, APT остаётся ручным шагом `make release-publish` одной командой.

## D10. Workshop для всех игр

- Проверено:
  - Workshop есть у S2 и у трёх EE, у оригиналов нет;
  - в моды EE нельзя класть `.dll`/`.exe`;
  - моды S2 — ресурсы и Blueprint через Zone Kit.
- Вывод: **сам редактор (exe) через Workshop распространить нельзя**. Через Workshop можно распространить только внутриигровой мод-компаньон.
- **Рекомендация:**
  - компаньон для EE — через Workshop;
  - компаньон для оригиналов — zip для `gamedata` (или установщик) на GitHub, ModDB, Nexus;
  - компаньон для S2 — позже, через Zone Kit.
- Загрузку в Workshop делает владелец со своего аккаунта: соглашение Steam Workshop принимает он.

## D11. Редактор внутри игры — ждёт владельца

- Предложение: мод, который из меню игры правит локальные сейвы.
- **Рекомендация: править загруженную игру, а не файл сейва.**
  - Как это выглядит: игрок загрузился → открыл окно компаньона (горячая клавиша или пункт в меню/PDA) → меняет деньги, предметы, ремонт, отношения, телепорт → сохраняется обычным сохранением игры.
  - В X-Ray это делается штатным Lua API: `give_money`, `alife():create`, `release`, `set_actor_position`. Это надёжнее, чем разбирать бинарный сейв из Lua, и не требует внешнего exe.
  - Правка файла сейва из главного меню потребовала бы запуска внешнего helper'а из мода, а для EE это запрещено.
  - Начать с POC на оригинальной ЗП (MOD-2).

## D12. Телепорт

- Предложение: телепорт по принципу проводников; в ТЧ проводников не было.
- **Рекомендация:** называть «Перенос (experimental)» и переносить только в известные безопасные точки.
  - Точки берутся из точек назначения переходов между уровнями в `all.spawn`/`game.graph`, есть во всех трёх играх. Для ТЧ проводники не нужны.
  - Для ЧН и ЗП дополнительно показывать направления проводников.
  - Порядок: перенос в пределах уровня (TP-3) → между уровнями (TP-4). Каждый шаг с L5, бэкапом и предпросмотром точки.
  - Произвольных XYZ не будет.
  - S2 — отдельный ресерч (TP-5).
  - В моде-компаньоне телепорт делается проще — штатными функциями игры.
