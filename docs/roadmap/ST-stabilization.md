## ST-2 — OTA на Linux end-to-end

**Кто:** Claude, пароль pkexec вводит владелец · **Размер:** M · **Зависит:** ST-1 · **Уровень:** L4

**Зачем.** Тест проверяет только, что команда собрана. Нужно доказать, что версия реально сменилась.

**Шаги.**

1. Собрать `.deb` версии N (текущий main) и N+1 (с изменённым `VERSION`) в `dist`.
2. Установить N: `sudo apt install ./dist/...N.deb`.
3. Поднять локальный manifest (`tools/build_release_manifest.py` + `python -m http.server` в каталоге `dist`) и направить на него приложение. Если переопределения URL манифеста нет, добавить env `SAVE_EDITOR_UPDATE_MANIFEST_URL` только для отладки и покрыть тестом.
4. В приложении: «Проверить обновления» → «Обновить» → владелец вводит пароль.
5. Проверить:
   - `dpkg-query -W stalker2-save-editor` показывает N+1;
   - приложение перезапустилось;
   - в «О программе» стоит N+1.
6. Повторить отказ: «Отмена» в pkexec → приложение сообщает об ошибке, а не молчит. Для этого `PKEXEC_HANDOFF_SCRIPT` должен сообщать код возврата, например через файл-маркер, который приложение читает при следующем старте.

**Приёмка.** `docs/evidence/OTA_LINUX_<дата>.md`: версии, команды, результат успеха и отказа.

## ST-8 — Починить автопубликацию релиза

**Кто:** Claude, секреты заводит владелец · **Размер:** M · **Зависит:** D9 · **Уровень:** L4

**Зачем.** С 0.6.0 каждый тег даёт красный CI, и релиз публикуется руками за 6 шагов.

**Шаги.**

1. `.github/workflows/build.yml`: разделить джобу `publish` на две.
   - `github-release` (`if: startsWith(github.ref, 'refs/tags/v')`, `permissions: contents: write`):
     - скачивает артефакты;
     - `tools/publish_release.py --artifacts ... --output release-output` (без R2);
     - `gh release create/upload` с `GITHUB_TOKEN`;
     - секреты не нужны.
   - `publish-r2-apt`:
     - первый шаг проверяет наличие секретов и выставляет output `enabled`;
     - если секретов нет — `::notice::` и все остальные шаги пропускаются, джоба зелёная;
     - если есть — текущие шаги R2, APT, Worker без изменений.
2. Web deploy:
   - новая джоба `web-deploy` на тегах: `wrangler pages deploy web` с тем же `CLOUDFLARE_API_TOKEN`, пропуск без секрета;
   - после деплоя smoke: `curl` на `pysrc.json` и проверка, что sha совпадает с собранным.
3. `docs/RELEASE.md`: новый порядок, что делает CI, что остаётся руками.
4. Проверить на `v0.7.3-rc1` (prerelease): Release создан автоматически, R2 пропущен или выполнен.

**Владелец** (я токены не вижу и не ввожу):

```bash
gh secret set CLOUDFLARE_API_TOKEN
gh secret set CLOUDFLARE_ACCOUNT_ID
gpg --export-secret-keys --armor <существующий KEY_ID> | gh secret set APT_SIGNING_KEY
gh secret set APT_SIGNING_KEY_ID
```

**Приёмка.**

- Тег `v0.7.3-rc1` → зелёный workflow и GitHub prerelease с артефактами и `SHA256SUMS`.
- С секретами: объекты в R2 читаются, `apt update` видит версию.
