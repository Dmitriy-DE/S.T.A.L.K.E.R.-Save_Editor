# Roadmap: состояние, план, кто что делает

Живой трекер проекта. Заменяет устаревшие `docs/plans/ROADMAP.md` и
`docs/tasks/INDEX.md` (очередь эпохи 0.3–0.5; уедут в архив задачей CL-3).

- [DECISIONS.md](DECISIONS.md) — разбор каждой идеи владельца, вердикт и решения, которые ждут владельца.
- Карточки задач по эпикам: [ST](ST-stabilization.md) · [KB](KB-s2-knowledge.md) · [ED](ED-editing.md) ·
  [CP](CP-content-packs.md) · [RL](RL-reliability.md) · [EE](EE-enhanced.md) · [MAC](MAC-macos.md) ·
  [MOD](MOD-ingame-workshop.md) · [TP](TP-relocation.md) · [CS](CS-csharp.md) · [CL](CL-cleanup.md) · [RS](RS-research.md)

Как пользоваться: статус меняет тот, кто берёт задачу, прямо в таблице ниже.
Одна карточка — одна ветка — один PR. Карточка написана так, чтобы её можно
было отдать исполнителю без пересказа контекста.

## Статусы и уровни готовности

`todo` · `in_progress` · `review` (PR открыт) · `done` · `blocked` (причина в карточке) · `owner` (ждёт действия владельца).

Фича не считается готовой по зелёным тестам. У каждой карточки указан нужный уровень:

| Уровень | Что доказано |
|---|---|
| **L1 IMPLEMENTED** | код есть |
| **L2 TESTED** | позитивные и негативные тесты, ruff, mypy, JS, свежий web bundle |
| **L3 PACKAGED** | работает из собранного `.deb`/`.exe` (и web после деплоя), а не только из `python -m ui` |
| **L4 RUNTIME** | сценарий пользователя пройден на реальной машине: клик → результат (OTA реально обновил версию, музыка реально играет) |
| **L5 GAME** | игра загрузила изменённый сейв, изменение видно, игра пересохранила, редактор снова разобрал |

Write-возможность получает `experimental` только с L5-доказательством в `docs/evidence/`.
`verified` — L5 на нескольких сейвах и сборках игры.

## Исполнители

| Кто | Сильные стороны | Что ему давать | Чего не давать |
|---|---|---|---|
| **Claude** (дорогой, умный) | архитектура, реверс форматов, writer'ы, безопасность, ревью, релизы, интеграция | ресерч форматов, всё что пишет в сейв, спецификации для Codex, ревью чужих PR, релизный конвейер | механическую работу, которую можно описать тестами |
| **Codex** (GPT-6 Luna: медленный, почти бесплатный, туповат) | долгие ограниченные задачи с чётким критерием «тест зелёный» | порт модулей на C# по golden-векторам, CI/скрипты, генераторы, удаление мёртвого кода, перенос тестов | архитектурные решения, новые write-возможности, что-то без проверяемого критерия. Не ставить на критический путь — он медленный |
| **Gemini** (быстрый, бесплатный, качество низкое) | быстрый веб-ресерч, сбор данных, черновые переводы, просмотр скриншотов | «найди и верни JSON с источниками», переводы строк, поиск обрезанного UI на скриншотах, конспекты документации | правки кода в репозитории без ревью; всё, что он вернул, проверяется автоматически (URL 200, картинка декодируется, плейсхолдеры `{0}` на месте) или Claude |

Правила для любых исполнителей:

- Личные сейвы и `fixture_*` — только локально, никогда в Git, в промпты и во внешние сервисы.
- Никаких новых write-возможностей без Claude-ревью и L5-доказательства (см. `AGENTS.md`).
- Codex и Gemini работают в своих ветках: `codex/<ID>`, `gemini/<ID>`. В `main` — только через PR с ревью Claude.
- Шаблон передачи задачи — в конце этого файла.

Режим токенов: ultracode только для ресерча (ED-2, EE-2, TP-1, MOD-1). Остальное Claude делает в low effort строго по карточке.

Прочитай AGENTS.md и карточку docs/roadmap/<файл>.md#<ID> целиком.
Сделай только то, что в разделе «Шаги». Не трогай файлы вне раздела «Файлы».

не обходи проверки и не меняй capability/writer.
Личные сейвы и пути пользователя не коммить и не выводи.
Результат: PR в main с описанием «что сделано / как проверено / что не проверено».
