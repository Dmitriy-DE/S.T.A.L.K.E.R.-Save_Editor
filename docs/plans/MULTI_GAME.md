# План: четыре игры серии и работа с реальными папками сохранений

> Вход для исполнителя. Читать целиком до первой строки кода.
> Карточки `M01…M09`; порядок в таблице — рабочий.

## Что нужно получить

Редактор сохранений для **четырёх** игр:

| Игра | Движок | Состояние |
|---|---|---|
| S.T.A.L.K.E.R. 2: Heart of Chornobyl | Unreal Engine 5 | работает: деньги и стаки инвентаря |
| S.T.A.L.K.E.R.: Call of Pripyat | X-Ray 1.6 | нет |
| S.T.A.L.K.E.R.: Clear Sky | X-Ray 1.5 | нет |
| S.T.A.L.K.E.R.: Shadow of Chernobyl | X-Ray 1.0 | нет |

В интерфейсе: выбрать игру, закинуть сейв, отредактировать. На десктопе —
указать путь к Steam / игре / папке сейвов **или** чтобы программа нашла сама и
дала выбрать слот прямо оттуда.

## Два разных по сложности куска

**S.T.A.L.K.E.R. 2** — игра свежая, формат закрытый, публичных описаний почти
нет. Текущий парсер знает два поля по найденной сигнатуре, и расширять его
можно только по доказательствам.

**Трилогия** — другое дело. Играм по пятнадцать лет, движок X-Ray разобран
моддерским сообществом вдоль и поперёк: есть открытые инструменты, описания
структур, парсеры alife. Это **не** реверс с нуля. Сначала найти документацию и
существующие реализации, и только пробелы в них закрывать своим исследованием.

Что у них общего с S2: ничего, кроме расширения `.sav`. Другой контейнер,
другое сжатие, другая раскладка. Поэтому формат — отдельная реализация на
движок, а не ветка в существующем парсере.

## Границы, которые нельзя перейти

- Не угадывать смещения. Поле принимается по минимум трём независимым парам
  сейвов и сверке с тем, что показывает сама игра.
- Не переиспользовать `MONEY_ANCHOR` и структуры S2 для трилогии.
- Байт-в-байт round-trip **до** любых правок. Не собирается обратно — не
  редактируем.
- Не показывать в интерфейсе игру, для которой нет парсера, даже заглушкой.
- Не писать в папку игры без явного подтверждения. Основной desktop Save пишет
  только в открытый слот после verified backup; технический export может писать
  новую копию через общий service API.
- Не ломать текущий контракт: `EditorService`, `EditPlan`, backup, CRC,
  round-trip, привязка к SHA источника.
- Личные сейвы в репозиторий не попадают: только хэши, смещения и выводы.

## Справочная информация

### Где искать пути сохранений

Пути зависят от игры, издания и launcher\'а, поэтому M03 начинается с
исследования, а не с кода. Покрыть надо: Steam, GOG, Game Pass/Microsoft Store,
переиздание Legends of the Zone Trilogy и Enhanced Editions, плюс оригинальные
розничные версии с патчами.

Подсказки, куда смотреть:

- PCGamingWiki — у каждой игры раздел Save game data location с разбивкой по
  изданиям. Самый быстрый старт.
- X-Ray читает корень пользовательских данных из `fsgame.ltx` рядом с игрой, и
  его можно переопределить. Программа обязана это уважать.
- Папка «Мои документы» локализуется: жёстко зашитое `Documents` найдёт не у
  всех.
- На Linux всё идёт через Proton, и документы лежат внутри префикса:
  `<library>/steamapps/compatdata/<appid>/pfx/drive_c/users/steamuser/`.

### Steam

| ОС | Корень |
|---|---|
| Windows | реестр `HKCU\Software\Valve\Steam` → `SteamPath`; запасной `%ProgramFiles(x86)%\Steam` |
| Linux | `~/.steam/steam`, `~/.local/share/Steam`, `~/.var/app/com.valvesoftware.Steam/data/Steam` |

Библиотеки — `<steam>/steamapps/libraryfolders.vdf`, текстовый VDF, парсится
своим кодом без новых зависимостей. Установленная игра —
`<library>/steamapps/common/<имя>`, манифест `appmanifest_<appid>.acf`.

App ID S.T.A.L.K.E.R. 2 — **1643320**, подтверждён: используется в
`steam_cloud.py`. ID остальных игр и всех переизданий исполнитель находит и
проверяет сам; непроверенное число в код не попадает.

### Что уже есть в проекте

| Нужно | Файл |
|---|---|
| пути по ОС, поиск helper | `editor/platforms.py` |
| загрузка декодера и регистрация чужого | `editor/codec.py` |

| неизменяемый план правок | `editor/models.py` |
| применение плана | `editor/prepare.py` |
| backup, атомарная запись, журнал | `editor/storage.py` |

Логика, общая для интерфейсов, живёт в `editor/`. Положишь в `ui/` — в
браузерную сборку не попадёт.

## Как проверять

Каждая карточка: сначала падающий тест, потом минимальная реализация, потом
`make check` и `make test`. CI гоняет Linux и Windows × Python 3.11/3.12,
поэтому работу с файловой системой в тестах подменять, а не полагаться на
машину исполнителя.
