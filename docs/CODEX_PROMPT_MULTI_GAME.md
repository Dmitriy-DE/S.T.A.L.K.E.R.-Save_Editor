# Задание исполнителю: несколько игр серии и работа с папками сохранений

Скопируй этот файл целиком в первое сообщение исполнителю. Ниже — всё, что
нужно, чтобы начать без дополнительных вопросов.

## Промпт

Ты работаешь в репозитории редактора сохранений S.T.A.L.K.E.R. 2.

Прочитай в таком порядке и не начинай кодить раньше:

1. `AGENTS.md` — неподвижные требования проекта.
2. `docs/STATUS.md` — что работает и что не доказано **сейчас**.
3. `docs/plans/MULTI_GAME.md` — план этой работы, включая справочные пути и
   границы.
4. Карточку, которую берёшь: `docs/tasks/M01.md` и далее по порядку.

Бери **одну** карточку за раз. Одна карточка = одна ветка = один PR. Не
объединяй, не забегай вперёд, не переписывай парсер «заодно».

Порядок работы внутри карточки:

1. Сначала тест, который падает по той причине, ради которой карточка заведена.
   Приложи его вывод.
2. Минимальная реализация, которая этот тест проходит.
3. `make check` и `make test`. Оба должны быть зелёными до PR.
4. В PR: что изменилось в поведении, какие команды гонял, какие exit codes,
   что осталось непроверенным.

Начни с **M01**. Она не требует ни одного чужого сейва.

## Что уже сделано — не переделывай

- Интерфейс один: Qt (`ui/`). Tkinter удалён намеренно.
- Ядро UI-free: `editor/` (service, models, prepare, storage, transactions,
  platforms, codec). Все интерфейсы ходят только через `EditorService`.
- Веб-сборка (`web/`) запускает **то же самое ядро** в браузере через Pyodide.
  `web/pysrc.json` генерируется из исходников; `make check` падает, если он
  отстал. Всё, что добавляешь в `editor/`, доступно и в вебе; всё, что
  добавляешь в `ui/`, — нет. Это влияет на то, где писать логику.
- CI зелёный: Linux и Windows × Python 3.11/3.12. Твой код обязан проходить
  обе ОС, поэтому файловую систему в тестах подменяй, а не полагайся на свою
  машину.
- Правки безопасны по построению: immutable `EditPlan`, привязка к SHA
  источника, backup, атомарная запись, round-trip. Ничего из этого не снимать.

## Чего делать нельзя

- Угадывать смещения, сигнатуры и структуры. Поле считается найденным только по
  evidence (см. `M06`), а не по одному совпадению.
- Переиспользовать `MONEY_ANCHOR` или структуры S.T.A.L.K.E.R. 2 для другой
  игры. Совпадение расширения `.sav` не значит ничего: старая трилогия — движок
  X-Ray, у неё общего с UE5-контейнером нет.
- Показывать в интерфейсе игру, для которой нет парсера. Пользователь выберет
  её, получит ошибку и решит, что сломана программа.
- Определять игру по имени файла или расширению. Только по содержимому.
- Писать в папку игры. Копия сохраняется туда, куда указал пользователь.
- Добавлять зависимости ради разбора `libraryfolders.vdf`. Формат текстовый,
  разбирается своим кодом.
- Трогать личные сейвы владельца или коммитить их. В репозиторий идут только
  хэши и выводы.

## Ключевой факт, из-за которого план такой

S.T.A.L.K.E.R. 2 — Unreal Engine 5, контейнер сжат Kraken, парсер знает два
поля по найденной сигнатуре. Shadow of Chernobyl, Clear Sky и Call of Pripyat —
движок X-Ray: другой контейнер, другое сжатие, другая раскладка.

Поэтому «поддержка других частей» — это **отдельный парсер на каждую игру,
реверсируемый с нуля по реальным сейвам**, а не ветка в существующем коде.
Сначала архитектура и работа с папками (M01–M05, чужие сейвы не нужны), потом
форматы (M06–M07, без корпуса не начинаются).

## Справочная информация

### Steam

| ОС | Корень Steam |
|---|---|
| Windows | реестр `HKCU\Software\Valve\Steam` → `SteamPath`; запасной `%ProgramFiles(x86)%\Steam` |
| Linux | `~/.steam/steam`, `~/.local/share/Steam`, `~/.var/app/com.valvesoftware.Steam/data/Steam` |

- Библиотеки: `<steam>/steamapps/libraryfolders.vdf`.
- Установленная игра: `<library>/steamapps/common/<имя>`, манифест
  `appmanifest_<appid>.acf`.
- **Linux + Proton:** сейвы лежат внутри префикса,
  `<library>/steamapps/compatdata/<appid>/pfx/drive_c/users/steamuser/...`.
  Без этого поиск на Linux вернёт пусто.

### App ID

- S.T.A.L.K.E.R. 2 — **1643320**. Подтверждён: используется в `steam_cloud.py`.
- Для старой трилогии ID и имена папок **проверь сам** на живой установке или в
  манифестах. В этот файл они намеренно не вписаны: непроверенное число,
  попавшее в код, потом выглядит как факт.

### Папки сохранений

- S.T.A.L.K.E.R. 2, Windows: `%LOCALAPPDATA%\Stalker2\Saved\SaveGames\`.
  В Steam Cloud путь `Stalker2/Saved/STEAM/SaveGames/Data/` — уже в коде.
- X-Ray-трилогия, Windows: `Documents\STALKER-<игра>\savedgames\`. Точные имена
  папок проверь.

### Команды

```bash
python3 -m pip install -r requirements.txt -r requirements-dev.txt
make check     # линтер, типы, синхронность генерируемых файлов, компиляция
make test      # тесты
make run       # запустить интерфейс
make web-serve # локальная веб-версия на http://localhost:8765
```

## Что считать сделанным

Кодовая карточка: падавший тест, минимальная реализация, зелёные `make check` и
`make test` на обеих ОС в CI, описанное поведение, честно названные ограничения.

Research-карточка: воспроизводимые хэши, подтверждённые значения, отвергнутые
кандидаты с причинами, область применимости. **Нет доказательств — статус
`blocked`, зависимая реализация не начинается.** Это не пожелание: половина
ценности проекта в том, что он не портит сейвы, о которых ничего не знает.
