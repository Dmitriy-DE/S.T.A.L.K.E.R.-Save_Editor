# M01 — Реестр форматов сохранений

**Зависимости:** —. **Gate:** code. **Priority:** P1.

## Зачем

Сейчас `save_format.py` — единственный и безымянный формат: `EditorService`
вызывает `inspect_save` напрямую. Пока игра одна, это нормально. Как только
появляется вторая, выбор формата расползётся по интерфейсам, и каждый начнёт
угадывать по-своему.

## Scope

Ввести `editor/formats.py`:

```python
class SaveFormat(Protocol):
    id: str            # "stalker2"
    title: str         # "S.T.A.L.K.E.R. 2: Heart of Chornobyl"
    def detect(self, data: bytes) -> bool: ...
    def inspect(self, data: bytes, *, with_inventory: bool = True) -> SaveInfo: ...
    def prepare(self, data: bytes, plan: EditPlan) -> PreparedEdit: ...
```

и реестр: `register(fmt)`, `formats()`, `by_id(id)`, `detect(data)`.

S.T.A.L.K.E.R. 2 регистрируется как **единственная** реализация, целиком поверх
существующих `save_format.inspect_save` и `editor.prepare.prepare_edit`. Ни
байта парсера не переписывается.

`EditorService` получает формат через реестр и пробрасывает его id в
`SaveInfo`/снимок, чтобы интерфейс мог показать, что именно он открыл.

## Чего не делать

Не вводить второй формат в этой карточке. Не менять `save_format.py`. Не
изобретать плагины с загрузкой из файлов — реестр статический, в коде.

## Проверка

- Реестр возвращает ровно один формат; `detect` на synthetic fixture даёт его.
- `EditorService.inspect` через реестр даёт тот же `SaveInfo`, что прямой вызов.
- Неизвестные байты: `detect` возвращает `None`, а не первый формат в списке.
- `make check`, `make test`.
