# M20 — Перенос предметов между слотами, поясом и рюкзаком X-Ray

**Зависимости:** M19. **Gate:** research → code. **Priority:** P2.

## Scope

Добавить для официальных оригинальных Shadow of Chernobyl, Clear Sky и Call of
Pripyat чтение и staging переноса actor-owned предмета между `slot`, `belt` и
`ruck`. Номер слота — 1…13. Перенос не меняет count, condition, upgrades,
оружие или соседние registry records.

S.T.A.L.K.E.R. 2, Enhanced Editions и моды остаются вне этой карточки. Если
для объекта нет точного place anchor, он показывается, но остаётся read-only.

## Подтверждённая схема

OpenXRay показывает порядок `u8` physical state → `u16 SInvItemPlace` →
condition в обычном inventory object. Для всех трёх original X-Ray specs
подтверждён `client_place_offset=1`; codec не ищет поле эвристическим сканером.
Подробности, ссылки на pinned исходник и read-only corpus находятся в
[XRAY_PLACEMENT](../evidence/XRAY_PLACEMENT_2026-09-16.md).

`EditPlan.placements` — immutable tuple уникальных троек
`(handle, placement_type, slot_id)`. Slot меняет type и slot, сохраняя
`base_slot_id`; belt/ruck меняют только type. Writer требует actor ownership,
точный anchor и повторный read-back.

## UI и безопасность

- Qt и web добавляют маленький position editor рядом с condition editor;
  изменения staged и попадают в общий список before → after.
- Capability включается только для original SoC/CS/CoP и помечается
  experimental; unknown/missing anchor получает понятную read-only причину.
- Preview/download не меняет исходный файл. Desktop сохраняет M16 backup,
  fresh SHA и read-back pipeline; web предлагает только новую локальную копию.
- Визуальный слой M19 не меняется: icon/fallback отображение не влияет на
  bytes и mutation eligibility.

## Результат — 2026-09-16

Реализованы source-backed placement codec, release-specific annotation,
immutable plan, Qt/web staging и writer для оригинальной трилогии. Read-only
корпус: SoC 6/6 parsed, 328 editable placements; CS 59/59 и 4034; CoP 171/171
и 27373. Игра не запускалась и исходные сейвы не перезаписывались, поэтому
M10 game load/re-save остаётся внешним gate.
