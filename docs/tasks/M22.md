# M22 — Воспроизводимый анализ S2 compact key ↔ prototype SID

**Зависимости:** M21. **Gate:** research → code. **Priority:** P2.

## Зачем

Read-only CFG catalog из M21 содержит официальные prototype SID, но это ещё не
доказывает, какое поле в `.sav` ссылается на такой SID. Без этого нельзя
безопасно добавить новый предмет, клонировать оружие или назвать найденный
объект только по совпадению числового ключа.

## Scope

- `editor/s2_mapping.py` — общий read-only анализ нескольких валидных S2
  samples;
- `tools/analyze_s2_mapping.py` — CLI, который печатает только SHA-256,
  агрегаты и opaque observations, без путей и payload;
- `tests/test_s2_mapping.py` — key-change, key-reuse и input-contract tests;
- evidence и статус задачи.

Анализ принимает личные сейвы только как локальный вход. Он не пишет исходник,
не создаёт edited copy, не загружает ничего в Steam Cloud и не меняет
capabilities.

## Критерий mapping gate

Mapping может стать confirmed только после контролируемой пары с известным SID
(новый предмет создан в игре), повторяемого object/registry diff минимум для
трёх SID из разных категорий и game load/re-save/read-back. Стабильность
трёхбайтового `type_key` между обычными сейвами сама по себе недостаточна;
reuse и смена ключа сохраняются в отчёте как evidence, но не превращаются в
human name.

## Результат — 2026-09-16

На четырёх доступных локальных S2 сейвах анализ нашёл 34 общих handle между
образцами. Для 13 handle compact key меняется, а ключ `052000` встречается у
двух разных handle. Ни один вход не был SID-labelled controlled acquisition,
поэтому mapping status остаётся `unconfirmed`, а S2 Add/clone/upgrade writer
остаются выключенными.

Подробный отчёт: [S2 mapping evidence](../evidence/S2_MAPPING_2026-09-16.md).
