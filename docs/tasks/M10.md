# M10 — Протокол проверки в игре

**Зависимости:** M06. **Gate:** research. **Priority:** P1.

## Зачем первая

Парсер собирает файл байт в байт, но это доказывает, что файл собран, а не что
игра его поймёт. Пока ни один отредактированный сейв не загружался в игре,
любая запись — предположение. Эта карточка снимает неопределённость со всех
последующих.

## Scope

Описать и выполнить воспроизводимую процедуру для каждой игры трилогии:

1. Взять сохранение, сделать копию, править **одно** значение (деньги).
2. Загрузить копию в игре. Записать: загрузилась ли, совпало ли значение,
   не сломалось ли что-то видимое.
3. Сохраниться в игре заново и разобрать получившийся файл своим парсером.
4. Записать результат в `docs/evidence/INGAME_VERIFICATION.md`: игра, версия,
   что менялось, что показала игра, хэши до и после.

## Почему шаг 3 обязателен

Если игра загрузила наш файл, но при повторном сохранении выдала структуру,
которую наш парсер больше не понимает, значит мы собрали что-то формально
валидное, но чужое движку. Это ловится только повторным сохранением.

## Результат

Для каждой игры — прошло или нет. Прошло: в `FormatCapabilities` включается
`edit_money`, остальные возможности открываются своими карточками по той же
процедуре. Не прошло: возможность остаётся выключенной, причина записана.

## Чего не делать

Не проверять на единственном сейве и не объявлять результат по одной игре
верным для трёх: версии движка разные.
