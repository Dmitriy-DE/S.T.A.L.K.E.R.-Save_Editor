# M23 — Безопасный X-Ray detach по известным registry-ссылкам

**Зависимость:** M20. **Gate:** research → code. **Priority:** P2.

## Зачем

Предыдущий `deep detach` удалял один actor-owned object record и проверял
только отсутствие предмета в inventory. Для объекта с дочерними registry
записями или с подтверждённым экипированным placement такая операция могла
оставить dangling reference либо сломать состояние экипировки.

## Scope

- `editor/xray_delete.py` — read-only анализ известных identity/parent edges;
- `editor/xray_save.py` — отказ до изменения OBJECT registry;
- `tools/build_web_bundle.py` и generated `web/pysrc.json` — сохранить общий
  browser import graph;
- `tests/test_xray_delete.py` — leaf, equipped, dependent и missing-object
  regression tests;
- `tests/test_docs_consistency.py` — проверка присутствия delete-модуля в
  browser bundle manifest;
- evidence, cross-platform contract и task status.

## Граница доказанности

Удаление разрешается только для actor-owned leaf object без явно
подтверждённого `equipped` storage и без дочерних parsed registry records.
Отсутствующий объект и объект из `unresolved_handles` блокируются. Полный
граф ссылок внутри opaque STATE/UPDATE, quest references, game load/re-save и
проверка конкретного релиза в игре остаются отдельными незакрытыми gates;
поэтому это усиление существующего structural `deep detach`, а не заявление
о полной семантической безопасности удаления.

## Результат — 2026-09-16

Добавлен immutable `XRayDeleteAnalysis`. Writer вызывает его перед каждым
удалением, показывает blocker с handle/dependent IDs и не пересобирает save при
отказе. Legacy fixtures без декодированного placement сохраняют прежнюю
совместимость: неизвестное storage не превращается в ошибочное утверждение,
что предмет экипирован.

Подробные source и negative-boundary notes: [X-Ray delete evidence](../evidence/XRAY_DELETE_2026-09-16.md).
