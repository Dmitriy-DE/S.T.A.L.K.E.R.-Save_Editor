## Реализация и локальное evidence

`packaging/build.py` — stdlib-only orchestrator. Он отказывается от
cross-OS target, вызывает PyInstaller onedir со spec, копирует только
публичные resources, создаёт deterministic `tar.gz`/`zip`, Debian staging с
`/usr/bin/stalker2-save-editor`, `BUILD_MANIFEST.json`, `SOURCE_COMMIT.txt` и
`SHA256SUMS`, а перед архивацией сканирует дерево на private inputs. Spec
включает Qt hooks, `data`, notices/provenance и Linux `vendor/ooz.abi3.so`;
Windows получает `ooz` только из platform wheel. Внешний SteamCloudFileManager
dependency удалён в SC-2 и в bundle не включается.

Проверено локально 2026-09-13 на Linux x86_64 (Python 3.14.4, временное
окружение PySide6 6.11.2/PyInstaller 6.22.3):

```text
python3 -m pytest tests/test_packaging.py -q                         -> 5 passed
/tmp/save-editor-ui-venv/bin/python packaging/build.py --target linux \
  --output-dir /tmp/save-editor-b01-artifacts                       -> exit 0
packaged SaveEditor-diagnostic --help                                -> exit 0
packaged SaveEditor-diagnostic --diagnostic                          -> exit 0, decoder=loaded
packaged SaveEditor --diagnostic                                     -> exit 0, decoder=loaded
offscreen Qt startup (2 s, then controlled SIGTERM)                  -> process stayed alive
tar/deb package scan                                                -> no private inputs; manifest/vendor present
dpkg-deb -I                                                         -> Architecture: amd64, Version: 0.3.0-experimental
```

Локальные artifact hashes намеренно не коммитятся: это build evidence для
данного временного host и Python 3.14, а обязательная beta lane строится на
Ubuntu 22.04/Windows 2022 с Python 3.11. В этом окружении Windows artifact,
реальная desktop DPI/keyboard проверка и GitHub runner не запускались. P03
runner issue #9 остаётся открытой после `startup_failure` без jobs; отсутствие
этих внешних данных не заменяется Linux mock.

## Рабочее место сборки (добавлено 2026-09-14)

Linux build разворачивает PyInstaller onedir с Python и Qt, затем копирует это
же дерево целиком в Debian staging: пик около 1.7 GiB на файловой системе
`--output-dir`. Запуск с `--output-dir` внутри tmpfs (`/tmp` по умолчанию всего
несколько GiB и лежит в RAM) заполняет её на стадии `.deb` и падал как голый
`shutil.Error` со списком наполовину скопированных путей — без указания
причины.

Теперь `packaging/build.py` проверяет свободное место до запуска PyInstaller
(`MIN_FREE_BYTES`, 3 GiB) и отдельно перехватывает сбой копирования в staging с
явным сообщением и остатком места. Практическое правило: собирать в каталог на
обычном диске и при необходимости задавать там же `TMPDIR`.
