# M24 — Safety-aware удаление в Qt и web

**Зависимость:** M23. **Gate:** code. **Priority:** P2.

## Зачем

Writer M23 уже отказывает для экипированных предметов, registry children и
unresolved targets, но UI до этого мог поставить такое удаление в staged plan.
Причина отказа должна быть видна на строке предмета, а не появляться только
после нажатия Preview.

## Scope

- общий `InventoryItem.remove_editable/remove_reason` snapshot metadata;
- X-Ray parser, Qt inventory view и web bridge/app;
- generated browser bundle и manifest consistency check;
- tests, evidence, task/status/spec documentation.

## Контракт

Для каждого разобранного X-Ray actor-owned inventory object parser использует
тот же M23 known-reference preflight. Leaf получает `remove_editable=True`;
equipped, dependent или unresolved object получает `False` и объяснение.
Qt отключает кнопку и показывает причину, web отключает control и сохраняет
причину в accessible tooltip. Writer остаётся обязательной второй защитой.

`storage=None` по-прежнему означает неизвестный placement и не превращается в
догадку. S2/Enhanced и любые форматы без `remove_items` остаются read-only.

## Результат — 2026-09-16

Добавлены per-item delete metadata, блокировка staged удаления в Qt/web и
проверка browser bundle import graph. Batch-анализ parent map выполняется за
один проход по registry, чтобы крупные CoP inventory snapshots не получили
квадратичную стоимость.
