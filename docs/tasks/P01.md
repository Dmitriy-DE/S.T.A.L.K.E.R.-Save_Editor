## Вход и выход

editor.codec.decompress(stream: bytes, unpacked_size: int) -> bytes; Linux legacy vendor fallback и platform-installed pyooz==0.0.8. Unsupported OS/arch → понятная ошибка.

## Реализация и evidence

`editor.codec` теперь разрешает только Linux/Windows x86_64 (также AMD64),
сначала импортирует платформенный модуль `ooz` из `pyooz==0.0.8`, а на Linux
при наличии файла использует legacy `vendor/ooz.abi3.so`. Windows никогда не
добавляет Linux vendor directory в `sys.path`. Ошибки содержат фактические
platform/arch и следующий шаг по зависимости. `decompress` сохраняет прежний
вызов `ooz.decompress(stream, unpacked_size)` и дополнительно требует
bytes-подобный результат ровно заявленного размера.

Красная фаза: до реализации сбор тестов завершался на
`ModuleNotFoundError: No module named 'editor.codec'`. После реализации:

```text
python3 -m pytest tests/test_codec.py -v                         -> 8 passed
python3 -m pytest tests/test_save_baseline.py -q                  -> 9 passed
make test                                                         -> 46 passed
make check                                                        -> exit 0
make selftest SAVE=.local/original-import-2026-09-13/D639C0F24C64FC164326E8967A8DCCBE.sav -> exit 0
```

Текущая native-проверка выполнена на Linux x86_64 (Python 3.14.4); в среде
использовался legacy vendor decoder, потому что `pyooz` не установлен как pip
пакет. Provenance-тест проверяет SHA и наличие manylinux x86_64 и win_amd64
wheels в `third_party/pyooz/provenance.json`. Реальный Windows import и
decode/rebuild smoke остаются обязательным P03/Windows-runner evidence; этот
Linux тестовый mock не является подтверждением Windows runtime.
