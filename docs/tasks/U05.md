Восстановление использует общий storage/service boundary; UI не читает и не пишет
байты напрямую. Карточка добавляет только журнал/hash browser и local restore,
не меняет формат сейва и не включает cloud restore.

## Контракт

- `inspect_backup(journal_path: Path) -> BackupRecord` проверяет version/status,
  наличие backup и SHA256. Состояния: `verified`, `missing`, `corrupt`.
- `list_backups(backup_dirs) -> tuple[BackupRecord, ...]` показывает журналы и
  orphan `*_ORIGINAL.sav`; отсутствующий или повреждённый journal не становится
  доступным для восстановления.
- `EditorService.restore_local(record_or_journal, output_path) -> RestoreReceipt`
  публикует проверенные bytes в новый путь атомарно. Existing destination и
  same-path отклоняются до записи; backup и journal не удаляются и не меняются.
- `BackupView` показывает дату/source/operation/hash/status, позволяет открыть
  папку, сделать hash preview и передать restore в `RestoreWorker`. Restore
  запускается вне UI thread и доступен только после свежего preview.

## Ограничения

Restore по умолчанию создаёт новую копию и не заменяет текущий сейв. Отдельный
подтверждённый in-place flow не добавлен. Проверки выполнены на Linux; native
Windows/DPI, GitHub runner и Steam/game semantics остаются отдельными gates.
