# M09 — Редактирование трилогии

**Зависимости:** M08. **Gate:** code. **Priority:** P3.

## Условие входа

Начинается только после того, как для игры принято чтение **и** round-trip
собирает файл байт в байт. Без этого правка означает «переписать файл, который
мы не умеем собрать обратно».

## Scope

`prepare` для форматов трилогии: деньги, количество подтверждённых стаков,
добавление из официального item catalog и глубокое удаление actor-owned
registry record. Через существующий `EditPlan`, с существующими гарантиями:
привязка к SHA источника, backup, атомарная запись, проверка результата после
сборки. Добавление использует только serializer family, для которой в том же
сейве найден registry template; неизвестная family или отсутствующий catalog
закрывают операцию.

## Обязательная проверка в игре

Отредактированный сейв загружается в самой игре, значение совпадает с
ожидаемым, игра продолжает работать после сохранения заново. Без этого
карточка не принята: побайтовый round-trip доказывает, что файл собран, а не
что игра его поймёт.

## Чего не делать

Move/equipment, reference-safe deletion, прочность, attachments/upgrades и
модификации не включать по догадке. Structural add/remove остаётся
ограниченным строгим catalog/template и reparse gate.

## Проверка

- Правка денег и подтверждённого ammo stack на синтетическом fixture и
  in-memory на локальном корпусе каждой игры.
- Catalog-backed add на representative save каждой оригинальной игры по всем
  десяти serializer families; synthetic deep-remove regression для actor-owned
  record.
- Исходный файл не изменяется; копия проходит повторный parser round-trip,
  SHA и общий backup/atomic export path.
- Запись в самой игре пока не выполнена; поэтому game-load/re-save gate не
  объявляется пройденным.
- `make check`, `make test`.

## Результат прохода 2026-09-15

`prepare_xray` редактирует actor money и оба подтверждённых ammo count поля
(STATE и UPDATE), сверяет исходный SHA и перечитывает результат. Добавлен
строгий object-window индекс (`SPAWN`/`STATE`/`UPDATE`) и length-changing
registry framing. Catalog-backed regression покрывает add для десяти
serializer families, а deep-remove — actor-owned record; writer не копирует
prototype bytes из архива, а использует только key/family из официального
catalog и template из исходного registry. Move, equipment, durability,
upgrades, attachments и reference-safe deletion остаются read-only. Enhanced
Editions и game-load/re-save gate остаются внешними ограничениями.

CLI теперь использует тот же catalog loader и принимает batch-добавление через
`python3 cli.py edit SAVE --add ITEM=COUNT`; результат проходит общий
backup/atomic export и повторное чтение. Это не расширяет список разрешённых
форматов и не заменяет игровой load/re-save gate.

Актуальный локальный проход содержит 277 passed; ruff, mypy и generated web
artifacts проходят. Linux package и Cloudflare deployment проверены отдельным
проходом; revision `f46c1cf8` отдал `app.js`, `pysrc.json` и `catalogs.json` с
HTTP 200.
Windows, интерактивный browser smoke, загрузка сейва самой игрой и Enhanced
Editions остаются открытыми gates. Подробные хэши и deployment read-back:
`docs/evidence/RELEASE_2026-09-15.md`.
