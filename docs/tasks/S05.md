## Реализация и evidence

`SteamWorker` теперь разделяет spawn и request под одним non-recursive lock.
На каждую сессию создаются один stdout reader и один stderr drainer; ответы
живут в отдельной очереди поколения. Timeout, EOF, malformed JSON или слишком
большая строка инвалидируют процесс, закрывают pipes, terminate/kill и делают
reap; следующая операция получает новый Ping и новую очередь. Запоздалый
ответ убитой сессии не может стать ответом нового запроса.

Для JSON response установлен предел `MAX_RESPONSE_BYTES = 256 MiB`, для
`ReadFile` — `MAX_FILE_BYTES = 64 MiB`, что оставляет запас для JSON envelope
текущего 27 MB save без бесконечного чтения. WriteFile по-прежнему передаёт
Vec<u8> потоковыми chunks; byte arrays не пишутся в лог.

`tests/fake_worker.py` покрывает normal, crash, delayed_once, malformed,
stderr_flood, chunked и oversize режимы без Steam. Красная фаза зафиксировала
deadlock старого recursive-lock пути; после реализации:

```text
python3 -m pytest tests/test_worker_lifecycle.py -v -> 7 passed
make test                                      -> 38 passed
make check                                     -> exit 0
```

Реальный Steam/helper release и Windows execution не проверялись; это остаётся
отдельным P02/P03/S06 gate.
