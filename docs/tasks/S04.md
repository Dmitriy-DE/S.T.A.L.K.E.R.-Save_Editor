## Реализация и evidence

`SaveInfo` теперь содержит `grid_handle_count`, `unresolved_handles` и
`warnings`; `InventoryLayout` сохраняет объявленное число cells и
диагностику. Parser продолжает отображать распознанные объекты, но неизвестный
`kind`, неоднозначный record, отсутствующую owned-ссылку, выход за границы,
duplicate position и sparse footprint помечает read-only/unresolved.
Известные stackable kind-коды ограничены `{4, 5, 7, 8}`; sentinel
`0xFFFFFFFF`, встречающийся в реальном owned array, учитывается как padding.

GUI показывает `parsed/total`, количество unresolved и причины в журнале.
CLI `info` печатает те же предупреждения, а `inventory` больше не скрывает
read-only записи и явно выводит `editable`, `read-only` или `unresolved`.
Move/detach/attach останавливаются на unresolved данных; обычные подтверждённые
stack/money сценарии не менялись.

Красная фаза: новые тесты сначала зафиксировали старое `editable_count=True`
для kind 99 и отсутствие полей `SaveInfo`. После реализации:

```text
python3 -m pytest tests/test_parser_coverage.py tests/test_save_baseline.py -v -> 16 passed
make test                                                           -> 31 passed
make check                                                          -> exit 0
make selftest SAVE=.local/original-import-2026-09-13/D639C0F24C64FC164326E8967A8DCCBE.sav -> exit 0
```

На D639 сохранён прежний structural/container self-test; один неизвестный
orphan теперь честно отмечается warning и не выбирается для attach. Реальная
игровая семантика, Windows и Steam Cloud по-прежнему не подтверждены.
