# M13 — Предметы: добавить, удалить, изменить количество

**Зависимости:** M10, M11. **Gate:** research → code. **Priority:** P2.

## Scope

Полноценная работа с инвентарём для игр, где это доказано:

- добавить предмет, выбранный из каталога игры;
- удалить предмет;
- изменить количество в стаке.

Предметы берутся **только** из каталога установленной игры. Предмета, которого
в этой игре нет, в списке быть не должно.

## Что проверить отдельно

- Патроны и стаки: количество живёт в двух местах состояния объекта, менять
  надо согласованно.
- Вес и объём: если игра считает переполнение, добавление не должно приводить к
  состоянию, из которого игрок не может выйти.
- Квестовые предметы: удаление может сломать сюжетную цепочку. Это уровень
  «опасно» из плана — предупреждение с конкретной причиной и обязательная
  резервная копия.

## Критерий приёмки

Добавленный предмет виден в игре, берётся в руки и работает. Удалённый исчезает
и не ломает загрузку. Проверено процедурой M10 на каждой игре отдельно.

## Проверка

- Добавление, удаление и изменение количества на корпусе.
- Предмет чужой игры не предлагается и отвергается при попытке.
- Исходный файл не меняется; побайтовая пересборка без правок не сломана.
- `make check`, `make test`.

## Текущий результат — 2026-09-15

Для официальной X-Ray трилогии уже реализованы catalog-backed add и deep
remove actor-owned registry records, а ammo stack count меняется согласованно
в STATE и UPDATE. Добавление использует только release-specific item catalog и
подтверждённый serializer family; неизвестные family, чужой catalog и
reference-safe/equipped deletion остаются запрещены. Qt и web показывают
официальный список предметов, staging и явные read-only причины. Структурные
counts и ограничения зафиксированы в
[XRAY_INVENTORY](../evidence/XRAY_INVENTORY_2026-09-15.md).

Capability для базовых add/remove/stack открыта только для трёх оригинальных
релизов согласно текущему owner acceptance; add/remove явно помечены как
experimental, потому что отдельного нового M10 game-load/read-back evidence
для каждой операции и каждой serializer family в репозитории нет. Enhanced
Editions и S.T.A.L.K.E.R. 2 остаются вне этого writer-а. Поэтому карточка
переведена из `waiting_dependencies` в `in_progress`, а полная игровая
приёмка не заявляется.
