## Реализация и evidence

`editor.transactions.upload_cloud()` теперь принимает immutable
`PreparedEdit`, использует точный `plan.source.locator` и выполняет
последовательность fresh ReadFile/SHA → exclusive original backup → exclusive
edited recovery → один WriteFile → SyncCloudFiles → wait `persisted=true` →
read-back SHA. До WriteFile stale source, wrong slot, read или backup error
вызывают `CloudTransactionError` и не пишут в remote. После WriteFile любая
ошибка возвращает `CloudReceipt(status="uncertain")` с recovery paths; retry и
rollback не выполняются. `verified` возвращается только после всех стадий.

`CloudReceipt` добавлен в общий immutable model; Tk flow использует этот
контракт и показывает пользователю reconciliation при uncertain. Live Steam
операций в тестах нет.

Красная фаза: до создания `editor/transactions.py` сбор завершался на
`ModuleNotFoundError: No module named 'editor.transactions'`. После реализации:

```text
python3 -m pytest tests/test_cloud_transaction.py tests/test_worker_lifecycle.py -v -> 15 passed
make test                                                                       -> 64 passed
make check                                                                      -> exit 0
```

Helper protocol и границы `is_persisted` зафиксированы в
[`docs/evidence/HELPER_PROTOCOL.md`](../evidence/HELPER_PROTOCOL.md): upstream
`v1.3.5`, commit `1388e292ec502257545bc0e12927a50d2141d8bf`. Его
`is_persisted()` — client-side Steamworks flag при асинхронной синхронизации;
поэтому read-back SHA остаётся обязательным. Реальный Steam/GFN, Windows и
игровой load/re-save не проверялись.
