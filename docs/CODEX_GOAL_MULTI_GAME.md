## Что за проект

Репозиторий: редактор сохранений S.T.A.L.K.E.R. 2 на Python. Один Qt-интерфейс в ui/, UI-free ядро в editor/, браузерная сборка в web/ на том же ядре через Pyodide, CLI в cli.py. CI зелёный на Linux и Windows x Python 3.11/3.12. Версия 0.5.8.

Что уже работает: чтение сейва S.T.A.L.K.E.R. 2, правка денег и количества подтверждённых стаков инвентаря, предпросмотр до записи, сохранение в новую копию, журнал резервных копий с восстановлением, вкладка Steam Cloud. Правки безопасны по построению: immutable EditPlan, привязка к SHA источника, backup, атомарная запись, CRC и побайтовый round-trip.

Прочитай до первой строки кода, в этом порядке: AGENTS.md, docs/STATUS.md, docs/plans/MULTI_GAME.md, docs/CODEX_PROMPT_MULTI_GAME.md, затем карточку docs/tasks/M01.md.

## Цель

Четыре игры:

1. S.T.A.L.K.E.R. 2: Heart of Chornobyl — Unreal Engine 5. Уже работает, не ломать.
2. S.T.A.L.K.E.R.: Call of Pripyat — движок X-Ray 1.6.02.
3. S.T.A.L.K.E.R.: Clear Sky — X-Ray 1.5.10.
4. S.T.A.L.K.E.R.: Shadow of Chernobyl — X-Ray 1.0004/1.0006.

Пользователь должен: выбрать игру, закинуть сейв, отредактировать. На десктопе — либо указать путь к Steam, к игре или к папке сейвов, либо чтобы программа нашла сама и дала выбрать слот прямо оттуда.

## Ключевой факт, из-за которого план такой

S.T.A.L.K.E.R. 2 и трилогия — это два разных по сложности куска, не путай их.

S.T.A.L.K.E.R. 2 свежий, формат закрытый, публичных описаний почти нет. Текущий парсер знает два поля по найденной сигнатуре. Расширять его можно только по доказательствам.

Трилогия — наоборот. Играм по пятнадцать лет, движок X-Ray разобран моддерским сообществом: есть открытые инструменты, описания структур сохранений, парсеры alife. Это НЕ реверс с нуля. Сначала найди документацию и существующие открытые реализации, разберись в них, и только пробелы закрывай собственным исследованием. Ищи по формату .sav движка X-Ray, по инструментам вроде xray_re-tools, по разборам alife и spawn, по описаниям заголовка сохранения и используемого сжатия. Учитывай, что версии формата у трёх игр разные, и что переиздания (Legends of the Zone Trilogy, Enhanced Editions) могут отличаться от оригиналов.

Общего у трилогии с S.T.A.L.K.E.R. 2 нет ничего, кроме расширения файла: другой контейнер, другое сжатие, другая раскладка. Поэтому формат — отдельная реализация на движок, а не ветка в существующем парсере.

Лицензии: проект под GPL-3.0. Чужой код можно брать только совместимый по лицензии, с сохранением копирайта и записью в THIRD_PARTY_NOTICES.md. Алгоритм, описанный в документации, можно реализовать самому — это не заимствование, но источник всё равно указывается.

## Что сделать в каждой карточке

M01 — реестр форматов. editor/formats.py: протокол SaveFormat с полями id и title и методами detect, inspect, prepare, плюс статический реестр register/formats/by_id/detect. S.T.A.L.K.E.R. 2 регистрируется как первая реализация целиком поверх существующих save_format.inspect_save и editor.prepare.prepare_edit. Ни байта парсера не переписывается. EditorService получает формат через реестр и пробрасывает его id в снимок, чтобы интерфейс показывал, что именно открыл. Второй формат в этой карточке не вводится.

M02 — определение игры по содержимому файла и честный отказ. Никогда по имени файла или расширению: и то и другое пользователь меняет. Каждый формат смотрит только свою сигнатуру и не бросает исключений на чужих байтах. Текст ошибки живёт в ядре и одинаков в Qt, CLI и вебе: что открыли, сколько весит, почему не подошло, какие форматы поддерживаются сейчас. Обязательно покрыть: пустой файл, обрезанный, мусор нужного размера, сейв другой игры, текстовый файл с расширением .sav.

M03 — где лежат сохранения. Эта карточка начинается с исследования, а не с кода, и результат исследования записывается в docs/evidence/SAVE_LOCATIONS.md. Найди и проверь пути сохранений для каждой игры и каждого издания: Steam, GOG, Game Pass и Microsoft Store, переиздание Legends of the Zone Trilogy, Enhanced Editions, оригинальные розничные версии с патчами. Для каждой строки записывай точный путь с переменными окружения, ссылку на источник и как проверено. Отдельно отметь, где путь зависит от языка системы, потому что папка «Мои документы» локализуется, и где данные лежат в Saved Games, а не в Documents. Учти, что X-Ray читает корень пользовательских данных из fsgame.ltx рядом с игрой и его можно переопределить — программа обязана это уважать. Полезный старт — PCGamingWiki, у каждой игры есть раздел Save game data location с разбивкой по изданиям. Строка без источника в отчёт не попадает, выдумывать пути нельзя.

Потом код в editor/platforms.py, не заводя второй модуль путей: steam_roots (Windows — реестр HKCU\\Software\\Valve\\Steam ключ SteamPath, запасной %ProgramFiles(x86)%\\Steam; Linux — ~/.steam/steam, ~/.local/share/Steam, Flatpak ~/.var/app/com.valvesoftware.Steam/data/Steam), steam_libraries (разбор steamapps/libraryfolders.vdf своим кодом, без новых зависимостей, битый файл пропускается с предупреждением), gog_roots и xbox_roots если исследование показало что нужны, installed_games по манифестам appmanifest_<appid>.acf, save_directories для каждой игры. Proton обязателен: на Linux игры идут через Proton и документы лежат внутри префикса, <library>/steamapps/compatdata/<appid>/pfx/drive_c/users/steamuser/. Без этого поиск на Linux вернёт пусто. App ID S.T.A.L.K.E.R. 2 равен 1643320 и подтверждён, он уже используется в steam_cloud.py; ID остальных игр и переизданий найди и проверь сам. Все функции принимают инъектируемые environ, home и корень файловой системы, как уже сделано в discover_helper, чтобы тесты собирали фальшивое дерево в tmp_path и проверяли обе ОС на любой машине. Ничего не создаём и не пишем: только чтение и перечисление.

M04 — выбор слота из найденной папки в Qt: имя слота, размер, время изменения, определённая игра, сортировка по времени изменения со свежими сверху. Открытие идёт тем же путём, что и ручной выбор файла. Пустой список не ошибка: показать, где искали, и оставить ручной выбор. Не открывать слот автоматически при старте. Не писать в папку игры. В вебе этой вкладки нет, потому что у браузера нет доступа к файловой системе — показать это честно, а не прятать.

M05 — ручное указание пути к Steam, к игре или к папке сейвов, с приоритетом над автопоиском. Хранить в существующем каталоге пользовательских данных через editor.platforms.user_data_dir, формат JSON с версией схемы. Битый или чужой файл настроек не роняет запуск: читать best-effort и продолжать с пустыми настройками. Если сохранённый путь исчез — сообщить и предложить выбрать заново.

M06 — контейнер X-Ray: заголовок с сигнатурой и версией, определение игры и издания, распаковка, и главное — байт-в-байт сборка обратно так, чтобы SHA-256 совпал с исходным файлом. Это одна карточка на все три игры трилогии. До совпадения round-trip никакие поля не ищутся вообще. Незнакомая версия формата — явный отказ с указанием версии, не догадка. Критерий приёмки: round-trip совпадает на каждом доступном сейве корпуса для всех трёх игр; не совпал хотя бы на одном — карточка не принята, причина записана.

M07 — Call of Pripyat, только чтение. Берётся первой, потому что это самая поздняя и аккуратная версия X-Ray в трилогии и она лучше всего описана сообществом. Реализовать формат stalker-cop в реестре: detect и inspect. Метод prepare пока отказывает явным сообщением, что редактирование для этой игры ещё не подтверждено. Доставать и показывать: деньги игрока, список предметов инвентаря с количеством и позицией, разобранные метаданные — версия формата, время игры, уровень. Всё неразобранное показывается честно как неразобранное, как уже сделано для S.T.A.L.K.E.R. 2 строкой про неподтверждённую схему.

M08 — Clear Sky и Shadow of Chernobyl, только чтение, тем же подходом. Различия версий движка вынести в таблицу данных, а не в ветвление кода: одна реализация X-Ray плюс таблица различий читается лучше, чем три почти одинаковых парсера. Enhanced Editions проверить отдельно: если формат отличается — это отдельная запись в таблице версий, а не «похоже, подойдёт». Сейв Clear Sky, открытый как Shadow of Chernobyl, и наоборот, должен дать отказ, а не мусорные значения.

M09 — редактирование трилогии. Входит в работу только после принятого чтения и совпадающего round-trip. Реализовать prepare для форматов трилогии: деньги и количество подтверждённых стаков, ровно то же, что уже умеет S.T.A.L.K.E.R. 2, через существующий EditPlan и с существующими гарантиями. Обязательна проверка загрузкой в самой игре: отредактированный сейв загружается, значение совпадает с ожидаемым, игра продолжает работать после повторного сохранения. Побайтовый round-trip доказывает, что файл собран, а не что игра его поймёт. Создание предметов, клонирование, удаление, прочность и модификации в эту карточку не входят.

## Критерий приёмки поля

Поле считается найденным, если выполнены все три условия: воспроизводится минимум на трёх независимых парах сейвов, где известно что менялось между файлами; значение совпадает с тем, что показывает сама игра; обратная правка возвращает исходное поведение. Одно совпадение — это совпадение, а не доказательство.

## Жёсткие правила, нарушение любого — переделывать

- Одна карточка = одна ветка = один PR. Не объединять карточки, не забегать вперёд, не рефакторить попутно то, о чём карточка не просит.
- Сначала тест, который падает по той причине, ради которой карточка заведена, с приложенным выводом. Потом минимальная реализация. Потом make check и make test, оба зелёные до PR.
- Не угадывать смещения, сигнатуры и структуры.
- Не переиспользовать MONEY_ANCHOR или структуры S.T.A.L.K.E.R. 2 для трилогии.
- Байт-в-байт round-trip до любых правок. Не собирается обратно — не редактируем.
- Не показывать в интерфейсе игру, для которой нет парсера, даже заглушкой: пользователь выберет её, получит ошибку и решит, что сломана программа.
- Определять игру только по содержимому, не по имени файла.
- Не писать в папку игры, правка уходит только в новую копию.
- Не снимать существующие гарантии: immutable EditPlan, привязка к SHA источника, backup, атомарная запись, CRC, round-trip.
- Не добавлять зависимости ради разбора libraryfolders.vdf или fsgame.ltx: форматы текстовые, парсятся своим кодом.
- Не трогать и не коммитить личные сейвы владельца; в репозиторий идут только хэши, смещения и выводы.
- Логика, общая для интерфейсов, живёт в editor/, а не в ui/: иначе она не попадёт в браузерную сборку.
- Непроверенные числа — App ID, смещения, версии — в код не попадают как факт.

## Когда останавливаться и спрашивать

Работай до конца всех девяти карточек. Не спрашивай разрешения на переход к следующей карточке.

Останавливайся и спрашивай только в трёх случаях: нужен реальный сейв игры, которого нет и который нельзя получить; тест падает на Windows по причине, которую нельзя воспроизвести локально и нельзя понять из логов CI; выполнение карточки требует нарушить правило из списка выше.

Если карточка упирается в отсутствие корпуса сейвов — не имитируй его и не подгоняй парсер под один файл. Поставь карточке статус blocked, запиши в docs/evidence/ что именно нужно получить (какие игры, какие пары сохранений, что должно меняться между ними), и переходи к следующей карточке, которая не заблокирована.
