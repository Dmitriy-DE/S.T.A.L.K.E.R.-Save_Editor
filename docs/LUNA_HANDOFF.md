# Инструкция GPT-5.6 Luna

## Контекст

Владелец играет через GeForce NOW, работает на Linux и хочет один редактор с Windows-версией. Исходники v0.3 уже импортированы, старые архивы сохранены. Научиться заново искать деньги не требуется. Новый Qt UI и Windows support ещё не реализованы.

## Каждый рабочий проход

1. Прочитать AGENTS.md, STATUS.md, спецификацию и одну карточку. Сначала **S01**.
2. Проверить git status, branch, dependencies/evidence. Не затирать чужие изменения и не менять несвязанные файлы.
3. Одна ветка `task/s01` (для следующих карточек соответствующий ID), один PR. Выполнить шаги карточки до её приёмки; не запускать весь ROADMAP одним большим запросом.
4. Для дефекта сначала тест с ожидаемым отказом на baseline. Минимальное исправление, затем targeted tests и весь доступный suite. Не писать тест, который только повторяет новую реализацию.
5. Сохранить scope/API. Новое имя/тип между задачами сначала изменить в spec+карточке, иначе следующая сессия получит несовместимый контракт.
6. Report: ID, что изменилось, какие сценарии проверены, команды/exit codes, commit/PR, ограничения. Обновить карточку и её запись tasks.json; GitHub issue получает ссылку на PR. Закрывать issue после принятого результата, не потому что код написан.
7. Остановиться на результате текущей карточки. Следующий проход получает следующий ready ID; не переключать модель и не запускать subagents автоматически.

## Нужный размер контекста

В обычной задаче читать актуальные документы и 2–6 относящихся к ней source/test файлов, расширяя чтение по вызовам. Не загружать полный персональный handoff на каждую мелкую UI-правку. Неподвижные runtime поля: MONEY_ANCHOR, count/weight offsets, CRC и full raw round-trip. Не переписывать save_format.py при переносе UI.

Если зависимость не выполнена, есть unknown binary structure или не хватает реальных данных: описать конкретный blocker и запрос на corpus. Разрешены анализ и подготовка тестов, не разрешено придумывать offset и подписывать кнопку «100%».

## Первый запрос исполнителю

```text
Работай только над S01 из docs/tasks/S01.md.
Прочитай AGENTS.md, docs/STATUS.md и docs/specs/CROSS_PLATFORM_EDITOR.md.
Выполни карточку на отдельной ветке, сохрани runtime v0.3 без изменений.
Добавь синтетические fixtures и проверки известных операций/отказов.
Проверь тесты, оформи PR и сообщи результат. Не мержи и не начинай S02.
```

## Шаблон передачи следующего шага

```text
Задача: <ID>
Ветка/commit/PR: <фактические значения>
Зависимости приняты: <ID и evidence>
Проверки: <команда, exit code, counts, OS>
Поведение: <конкретный before/after>
Не проверено: <Windows/cloud/game либо другое ограничение>
Следующий ready ID: <ID по dependencies, не автоматическое поручение>
```

## Полезные команды

Текущая база:

```bash
make check
python3 cli.py info /absolute/path/to/save.sav
make selftest SAVE=/absolute/path/to/original-D639.sav
```

После S01: `python -m pytest tests`. После U02 сначала установить pinned requirements-ui и иметь Qt test environment. Windows cmd не расширяет shell wildcard как bash: не использовать `tests/test_*.py` как путь в общей CI-команде.

Личные fixtures только в `.local/` или другом пользовательском пути; fresh clone должен проходить synthetic suite без них. Список локальных originals: `.local/original-import-2026-09-13/MANIFEST.json`.
